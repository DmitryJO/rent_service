# Техническое задание (ТЗ) проекта Rent Service

## 1. Общие сведения
Сервис аренды вещей, предоставляющий возможность пользователям (клиентам) бронировать различные предметы из предопределённых категорий. Администраторы управляют каталогом, заказами и настройками системы.

## 2. Категории арендуемых вещей
- **Стройка** – инструменты и оборудование для строительных работ.
- **Съёмка** – камеры, объективы, штативы, осветительное оборудование.
- **Игровые приставки** – консоли, контроллеры, аксессуары.

Для каждой вещи хранится:
- название
- описание
- состояние
- цена за день
- наличие (кол‑во)
- изображения (URL)

## 3. Роли и права
| Роль | Права |
|------|-------|
| **Администратор** | Управление заказами (бронирование, изменение, отмена), добавление/удаление категорий, изменение стоимости, загрузка изображений, изменение условий аренды. |
| **Пользователь** | Регистрация/аутентификация, просмотр каталога, поиск/фильтрация, создание бронирования (указание ФИО, телефона, даты/времени), просмотр и отмена своих заказов. |
| **Модератор** *(опционально)* | Просмотр всех заказов, блокировка пользователей, аудит логов. |

## 4. Функциональные требования
1. **Регистрация и аутентификация** – JWT + Refresh токены, Spring Security, OAuth2 Resource Server.
2. **Поиск и фильтрация** вещей по категории, цене, наличию, дате доступности.
3. **Бронирование** – пользователь указывает ФИО, телефон, выбирает дату/время или период. При подтверждении создаётся заказ.
4. **Управление заказами** – администратор может менять статус, отменять, продлевать.
5. **Оплата** – интеграция с платёжным шлюзом (необязательно в первой версии, но предусмотрена API‑точка).
6. **Отзывы и рейтинг** – пользователи могут оставлять отзывы о вещах после завершения аренды.
7. **Уведомления** – email/SMS о подтверждении, приближении срока возврата, отмене.
8. **Работа с изображениями** – загрузка в S3/MinIO, хранение только URL в БД, выдача подписанных URL.

## 5. Нефункциональные требования
### 5.1 Безопасность
- Аутентификация/авторизация: JWT, Refresh токены, Spring Security, OAuth2 Resource Server.
- Защита от CSRF (отключить для REST), XSS, SQL‑инъекций (Hibernate + валидация).
- Ограничение количества запросов – Bucket4j или Resilience4j (Rate Limiting).
- Логирование безопасности: неудачные логины, смена пароля, попытки доступа к чужим ресурсам. Пароли не должны попадать в логи, сессии очищаются при logout.
- Роли: `ROLE_USER`, `ROLE_ADMIN`, `ROLE_MODERATOR`.

### 5.2 Производительность
- API‑ответы: p95 < 200 ms для чтения, < 500 ms для записи.
- Кеширование часто запрашиваемых данных – Caffeine + Redis.
- Индексы в БД по `user_id`, `item_id`, `status`, `start_date`.
- Избегать N+1 запросов (использовать `@EntityGraph` или `JOIN FETCH`).

### 5.3 Масштабируемость и доступность
- Сервис stateless, всё состояние в Redis или БД.
- Горизонтальное масштабирование: несколько инстансов Spring Boot за балансировщиком (NGINX/ALB). На старте достаточно одного инстанса.
- База данных: PostgreSQL с репликами для чтения, PgBouncer для пуллинга соединений.
- Консистентность важна (CP по CAP). При бронировании использовать пессимистичную блокировку (`SELECT … FOR UPDATE`) и оптимистичную блокировку (`@Version`) для сущности `RentalOrder`.

### 5.4 Хранение данных
- Объекты (изображения) хранятся в S3/MinIO, в БД только URL.
- Миграции схемы – Flyway или Liquibase, без ручных скриптов.

### 5.5 Оперативные требования
- API‑First: OpenAPI 3 (Swagger) с самого начала.
- Версионирование API: `/api/v1/...`, `/api/v2/...`.
- Мониторинг и метрики – Spring Boot Actuator, Prometheus/Grafana.

## 7. Архитектурные диаграммы (описание)
- **Клиент** → **API‑Gateway (NGINX)** → **Spring Boot сервис** (stateless) → **PostgreSQL**, **Redis**, **S3/MinIO**.
- При бронировании сервис открывает транзакцию, делает `SELECT … FOR UPDATE` по выбранному предмету, проверяет доступность, сохраняет заказ с `@Version` для оптимистичной блокировки.

## 8. План разработки (минимальный MVP)
1. Проектная настройка (Maven, Spring Boot, PostgreSQL, Flyway).
2. Модели: `User`, `Item`, `Category`, `RentalOrder`.
3. Реализация аутентификации (JWT) и ролей.
4. CRUD для категорий и вещей (только для админа).
5. API поиска и фильтрации вещей.
6. Бронирование с пессимистичной блокировкой.
7. Тесты покрывающие бизнес‑логику бронирования.
8. Интеграция с S3 (загрузка изображений) и генерация подписанных URL.
9. Документация OpenAPI, Swagger UI.
10. Мониторинг, логирование, rate‑limiting.

## 9. Приложения
- **OpenAPI спецификация** – `src/main/resources/openapi.yaml`.
- **Flyway миграции** – `src/main/resources/db/migration/V1__init.sql`.
